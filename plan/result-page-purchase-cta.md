# 結果頁收單改版：購買按鈕 + 加 LINE

## 背景／斷點

目前結果頁是購買路徑的終點，但有三個斷點：

1. 每張香氣卡只有一個「查看更多 →」，連到 ECPay 的**精油 5mL／10mL 單買頁**，跟 IG 上講的「噴霧／訂閱」對不起來。
2. 結果頁沒有「加 LINE」按鈕，只有「追蹤 IG」。從 IG 主頁第一個連結直接來做測驗的人，做完就離開了，進不到 LINE。
3. 沒辦法知道哪一種植物結果帶來了購買（沒有來源標記）。

## 目標

- 結果頁每支推薦香都能**直接下單**（噴霧單買／訂閱）。
- 結果頁有一個明顯的「加 LINE 跟我聊」，讓還沒準備好買的人有地方去。
- 改的是資料，不是每個植物各改一次：三支香（夜和／朝光／暖居）的連結只寫一次。

## 已決定（2026-11-12）

- 按鈕：**兩顆**，「單買噴霧」＋「訂閱這支」（A1）。
- LINE 連結：`https://lin.ee/A9iq98L`（官網頁尾用的同一個，帳號 @349nwwah）。
- 還缺：三支香的噴霧單買頁、訂閱頁網址（共 6 個）。
- 品牌共有 7 支配方（夜和、暖居、朝光、日暮、花綻、花筏、思慕），測驗只推其中 3 支（夜和、暖居、朝光）。**主推夜和、暖居**。

每種結果都至少有一張夜和或暖居，不需要改推薦對應和文案。另外 4 支（日暮、花綻、花筏、思慕）不放進結果頁，在 LINE 區塊寫「還有 4 支配方，加 LINE 幫你配」。

## 實作內容

### 1. 資料結構（`js/data/plants.js`）

新增一個集中的商品表，三支香各寫一次：

```js
export const products = {
  oboro:    { name: "夜和 Oboro Night",    spray: "...", subscribe: "...", oil: "...914690" },
  sumi:     { name: "朝光 Sumi Dawn",      spray: "...", subscribe: "...", oil: "...920152" },
  komorebi: { name: "暖居 Komorebi Haven", spray: "...", subscribe: "...", oil: "...920061" },
};
export const LINE_URL = "...";
```

每個植物的 `scent.similar` / `scent.balance` 改成用 `product: "oboro"` 指向商品表，保留原本的 `text`（植物專屬文案不變）。`name` 從商品表帶，`share.js` 分享卡會一起改讀這裡。

### 2. 畫面（`js/ui.js` 的 `renderScents()`）

每張香氣卡底部：

```
相似香氣｜你會自然喜歡的味道
夜和 Oboro Night
偏涼、偏安定的香氣座標……
[ 單買噴霧 ] [ 訂閱這支 ]
也有精油 5mL／10mL →
```

香氣區塊下方、分享區塊上方，新增一個獨立區塊：

```
還不確定哪支適合你？
[ 💬 加 LINE 跟我聊 ]   ← 綠色 LINE 按鈕，全寬
```

（「追蹤 IG」維持在分享區不動。）

### 3. 來源標記

所有連結加上 `?utm_source=quiz&utm_medium=result&utm_content=<植物key>`，LINE 連結視格式加參數。ECPay 頁面不一定讀得到，但至少 GA／LINE 後台能看到流量從測驗哪個結果來。若 ECPay 會擋參數，就只加在 LINE 上。

### 4. 樣式（`css/style.css`）

- 新增 `.scent-actions`、`.scent-btn--primary`、`.scent-btn--secondary`、`.line-cta`。
- 手機優先：兩顆按鈕並排各 50%，高度 ≥ 44px；520px 以上加大內距。
- 沿用現有暖色系；LINE 按鈕用 LINE 綠 `#06C755`。

### 5. 快取

`index.html` 的 `?v=3` 改成 `?v=4`，避免舊手機吃到舊版 JS。

## 不會受影響

- 分享結果圖：用的是 `share/*.png` 預先產生的圖片，不會把按鈕截進去。
- 測驗題目、計分、動畫：不動。

## 驗證

- 本機開啟，6 種結果逐一檢查：按鈕連結對到正確的香、相似香是主推樣式。
- 手機寬度（375px）檢查按鈕不擠、不換行破版。
- push 到 `main` 後，GitHub Pages 線上版再點一次全部連結。
